2. API SERVER (artifacts/api-server) - Express 5 + TypeScript
--------------------------------------------------------------
Tech Stack:
- Express 5, TypeScript, Node.js
- Zod for validation (@workspace/api-zod)
- Pino for logging
- CORS, rate limiting
- Drizzle ORM (for DB integration)

API Endpoints:

Health & Status:
- GET /api/health - Health check

Analysis (POST /api/analyze):
- POST /api/analyze - Analyze recording (transcript + duration)
  * Validates transcript and duration
  * Computes deterministic metrics (WPM, fillers, pauses)
  * Runs content analysis via LLM
  * Saves session to store
  * Returns full analysis with scores

- POST /api/analyze/content - Content-only scoring
  * Scores grammar, vocabulary, structure, relevance
  * LLM-based with rubric and anchors
  * Strips fences, retries once on parse failure, normalizes

- POST /api/analyze/retry - Retry comparison
  * Compares new attempt with previous session
  * Computes deltas for metrics and scores
  * Reuses previous session's prompt_text

- POST /api/analyze/ideal - Generate ideal answer (503 if no LLM configured)

- GET /api/analyze/:id - Retrieve saved analysis by session ID

Speech (POST /api):
- POST /api/transcribe - Upload audio, get transcript + word timings + acoustics
  * Forwards to ASR service (http://127.0.0.1:8001)
  * Validates file type/size
  * Computes deterministic metrics
  * Returns words with timestamps

- POST /api/analyze/metrics - Compute metrics from transcript + optional word timings
- POST /api/analyze/events - Detect speech events (silences, filler bursts, repairs)
- POST /api/analyze/unified - Unified scoring combining metrics, acoustics, content + feedback

Core Libraries:
- analysis.ts - Core analysis logic, scoring
- metrics.ts - WPM, fillers, pauses, lexical diversity (pure functions)
- content-analysis.ts - LLM content scoring with normalization
- speech-events.ts - Timestamped speech events detection
- unified-scoring.ts - Combined scoring across modalities
- event-feedback.ts - Event-aware feedback generation
- session-store.ts - In-memory session storage
- retry-comparison.ts - Attempt comparison logic
- progress.ts - User progress tracking
- calibration.ts - Calibration utilities


3. ASR SERVICE (artifacts/asr-service) - Python + faster-whisper
----------------------------------------------------------------
Tech Stack:
- FastAPI/Flask style (app.py), Python
- faster-whisper for local transcription
- librosa for audio processing/acoustics
- numpy, soundfile, av

Features:
- Local faster-whisper transcription with word timestamps
- Custom initial prompt to preserve disfluencies (um, uh, etc.)
- Audio validation (format, size, duration 30-180s)
- True audio duration from decoded samples
- Temporary file cleanup
- Acoustic analysis (pitch variation, voiced ratio, energy variation, silence)

API Endpoints (app.py):
- POST /transcribe - Transcribe audio file
  * Accepts raw audio body with X-Audio-Filename header
  * Validates format/size/duration
  * Returns transcript, words with start/end timestamps, duration, acoustics

Modules:
- asr.py - Core transcription logic, model loading (singleton with double-checked locking), validation
- acoustics.py - Acoustic feature extraction
  * Pitch variation in semitones (via librosa.pyin)
  * Voiced ratio
  * Energy variation (RMS coefficient of variation)
  * Silence detection via librosa.effects.split with top_db threshold
  * All features return None on failure (no fake defaults)

Configuration (env vars):
- WHISPER_MODEL (default: base)
- WHISPER_DEVICE (default: cpu)
- WHISPER_COMPUTE_TYPE (default: int8)
- MIN_AUDIO_SEC (default: 30)
- MAX_AUDIO_SEC (default: 180)
- MAX_UPLOAD_BYTES (default: 12MB)


4. SCORING & METRICS SYSTEM
---------------------------
Deterministic Metrics (metrics.ts):
- WPM (words per minute) over total duration
- Articulation rate (excluding pauses)
- Pauses from gaps between consecutive words (count, total, avg, longest)
- Pause threshold: 0.8s (configurable)
- Fillers (word-boundary regex): um, uh, er, ah, you know, I mean, sort of, kind of
- Possible fillers (reported separately): like, so, right, actually, basically, literally
- Lexical diversity (type-token ratio on fixed window)
- Average sentence length

Content Scoring (content-analysis.ts - LLM):
- Scores: grammar, vocabulary, structure, relevance (1-10)
- Mode-specific context: general, interview, debate
- Rubric with anchor descriptions per band
- Grammar mistakes with corrections
- Strengths, weaknesses, suggestions
- Temperature 0.2-0.3, JSON output with retries
- LLM does NOT produce filler counts/confidence/pace (can't hear audio)

Unified Scoring (unified-scoring.ts):
- Combines fluency (deterministic), delivery (acoustics), content (LLM)
- Tempo stability, speech-to-pause ratio
- Fluency gating multiplier
- Pace scored against 120-160 WPM band
- All weights/thresholds as named constants

Speech Events (speech-events.ts):
- silence_event (medium 0.8s, high 1.5s thresholds)
- filler_burst (3+ fillers in 10s window, overlapping merged)
- repair_restart (repeated words within 0.7s, repair markers)
- Each event has type, start/end, severity, score, evidence, message

6. KEY TECHNIQUES & PRINCIPLES
-------------------------------
- Reference-only approach: Study external repos for ideas, reimplement in own code
- No fake defaults: Missing measurements return null/"not available"/explicit errors
- Word-boundary matching for fillers (prevents false positives like "number")
- True timestamps from word-level data, never estimated
- Acoustic features computed independently with per-feature error handling
- LLM used only for content scoring, never for audio-based metrics
- Editable transcript flow for re-scoring without re-upload
- Event-driven feedback with evidence-based recommendations
- Privacy-first: video processing can run in-browser (MediaPipe), raw video not stored by default
- Deterministic metrics are pure/testable functions
- Comprehensive unit tests for metrics, events, scoring
- Rate limiting on analyze/transcribe endpoints
- CORS configuration via env vars

8. WORKFLOW
-----------
1. User records video/audio in browser (Practice Room)
2. Audio transcribed via API -> ASR service (faster-whisper) with word timestamps
3. Deterministic metrics computed from transcript/word timings
4. Acoustic features extracted from audio
5. Content scored by LLM (grammar/vocab/structure/relevance)
6. Unified scoring combines all modalities
7. Speech events detected from timestamps
8. Event-aware feedback generated
9. Results displayed with timeline, scores, recommendations
10. Session saved for history/progress tracking

10. METRICS COMPUTED
--------------------
Deterministic (from transcript/word timestamps):
- WPM (words per minute) over total duration
- Articulation rate (excluding pauses)
- Pause detection: count, total time, average, longest (gap > 0.8s)
- Fillers: scored fillers (um, uh, er, ah, you know, I mean, sort of, kind of) via word-boundary regex
- Possible fillers reported separately (like, so, right, actually, basically, literally)
- Lexical diversity (type-token ratio on fixed window)
- Average sentence length
- Tempo stability (std of WPM across segments)

Acoustic (from audio):
- Pitch variation in semitones (std of log-frequency via librosa.pyin)
- Voiced ratio
- Energy variation (RMS coefficient of variation)
- Silence ratio and intervals (via librosa.effects.split with top_db)
- All with per-feature null-on-failure

Content (LLM):
- Grammar, Vocabulary, Structure, Relevance scores (1-10)
- Specific grammar mistakes with corrections
- Strengths, improvements, actionable tips
- Rubric-based scoring with anchors per band

Unified Scoring:
- Fluency (from deterministic metrics)
- Delivery (from acoustics)
- Content (from LLM)
- Overall score with weights/thresholds as named constants
- Fluency gating multiplier
- Pace scored against 120-160 WPM band

11. SPEECH EVENTS
-----------------
- silence_event: gaps > 0.8s (medium) and > 1.5s (high)
- filler_burst: 3+ scored fillers in 10s sliding window (merged)
- repair_restart: repeated word within 0.7s or repair markers (I mean, sorry, let me rephrase, what I meant was)
- Each event: type, start, end, severity, score, evidence, message
